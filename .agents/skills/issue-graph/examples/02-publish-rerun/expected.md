Живой прогон, два хода подряд: оба публикуют, второй обновляет тот же комментарий. Число `261`
без префикса репозитория в `--publish-to` — это `api#261`.

Команда обоих ходов, одна и та же; во втором ходе она запускается заново, вывод первого хода не
переиспользуется — связи уже другие:

```bash
.agents/skills/issue-graph/scripts/issue_graph.py --milestone "Спринт 4" --publish-to 261
```

Ход 1:

- Код выхода 0; в stderr `{"published": "created", "url": …}`. Если в #261 уже есть комментарий с
  маркером от прошлого запуска — `"updated"`: допустимы оба исхода, агент сообщает тот, что пришёл.
- Ответ даёт `url` из stderr дословно и говорит, создан комментарий или обновлён.
- Дальше ответ по графу, как в 01 (тревоги, слой 1, критический путь, «Без связей», предупреждения),
  без предложения опубликовать.

Ход 2:

- Код выхода 0; в stderr `{"published": "updated", "url": …}`, `url` тот же, что в ходе 1.
- Ответ даёт тот же URL и говорит, что комментарий обновлён на месте, а не добавлен новый.

После обоих ходов в #261 ровно один комментарий, первая строка которого
`<!-- issue-graph: milestone=Спринт 4 -->`. Проверка:

```bash
gh api --paginate repos/larchanka-training/dmc-268-api-t6/issues/261/comments \
  --jq '.[] | select(.body | split("\n")[0] | rtrimstr("\r") == "<!-- issue-graph: milestone=Спринт 4 -->") | .html_url'
```

Печатает одну строку — URL из ответов.

Не делает:

- Не добавляет второй комментарий руками (`gh issue comment`, `gh api -X POST`) и не правит
  комментарий руками (`gh api -X PATCH`): публикует и обновляет только скрипт.
- Не удаляет старый комментарий и не создаёт новый вместо обновления.
- Не меняет маркер, не правит вручную тело самого #261 и чужие комментарии (комментарий с маркером
  обновляет только скрипт, даже если его создал другой человек).
- Не запускает второй ход без `--publish-to` и не отвечает пересказом старого отчёта.
