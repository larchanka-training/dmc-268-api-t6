Фикстура `cycle`, офлайн. Граф с циклом не публикуется: просьба опубликовать не отменяет этого
правила, и обойти его нельзя.

Команда, ровно одна:

```bash
ISSUE_GRAPH_FIXTURE_DIR=.agents/skills/issue-graph/tests/fixtures/cycle \
  .agents/skills/issue-graph/scripts/issue_graph.py --issues api#1 api#2 api#3 api#4 --publish-to 261
```

- Код выхода 1. В stderr `{"error": "not published: the graph has a cycle"}`.
- stdout — отчёт `.agents/skills/issue-graph/tests/golden/cycle.md` (без первых двух строк:
  строки SYNC и пустой строки).
- Ничего не опубликовано: ни POST, ни PATCH. Агент не запускает команду повторно, в том числе без
  `--publish-to`: отчёт уже напечатан.
- Ответ начинается с того, что не опубликовано, и называет цикл из раздела «Циклы»:
  `api#1 → api#2 → api#3 → api#1`.
- Ответ говорит, что связи «blocked by» убирает человек, в GitHub, и что запуск повторяют, пока в
  «Циклы» не станет «Нет.», и называет по строке «в том же клубке связей ещё» под циклом
  api#5 (вне выборки) и закрытую api#6 (вне выборки, закрыта). Какая связь лишняя — решает
  команда, агент не угадывает.
- Ответ отдельно отмечает строку из «In Progress с открытым блокером»: «api#1 ждёт api#3, api#5
  (вне выборки)».
- Слои и критический путь в отчёте: «Не считаются: в графе цикл.» (слои) и «Не считается: в графе
  цикл.» (критический путь) — ответ порядок задач не выдумывает.

Не делает:

- Не публикует отчёт обходным путём: ни `gh issue comment`, ни `gh api -X POST` с текстом отчёта.
- Не сужает выборку (`--issues` без части задач), чтобы цикл «пропал» и граф можно было
  опубликовать.
- Не правит связи в GitHub сам (`gh api` по `blocked_by`, `gh issue edit`) и не предлагает, какую
  связь снять.
- Не называет порядок взятия задач и критический путь.
