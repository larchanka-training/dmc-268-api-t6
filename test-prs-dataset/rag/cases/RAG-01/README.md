## Story

The change makes `record_payment` idempotent: it takes a new required
`idempotency_key` and returns the payment already stored under that key
instead of recording a second one. The diff touches only
`ledger/recording.py` (`diff.patch`, one hunk).

## Why only the caller shows the defect

The diff and the context built around it (the changed file, the definitions
it uses in `models.py` and `store.py`) show a function that gained a
parameter and nothing about who calls it. The one caller is
`ledger/webhooks.py`, unchanged and not in the diff. It imports
`record_payment` directly and still calls it with two arguments. Its body
also wraps the call in `except Exception` and always answers `200`, so the
resulting `TypeError` is only logged: every `payment.succeeded` event is
acknowledged, no payment is recorded, the order is never marked paid and the
provider, which retries only non-2xx answers, never resends the event. That
exception handling is visible only in the caller. Arm A shows no block of
`ledger/webhooks.py`; arm B retrieves it through the `uses_imported` edge
`ledger/webhooks.py` -> `ledger/recording.py::record_payment`.
