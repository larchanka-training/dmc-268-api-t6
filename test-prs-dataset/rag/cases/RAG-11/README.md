## Story

Support gets an operator-facing entry point for account erasure requests. The
change adds `run_erasure(account_id, confirmed)` to `erasure/requests.py`
(`diff.patch`, one hunk): it writes an audit record, calls `purge_account` and
records the count it returns. The same hunk adds a docstring line to the
existing `log_request`, a compatible change that does not touch its signature
or behaviour.

## Why L4 alone suffices

`purge_account(account_id, *, dry_run=True)` in `erasure/purge.py` is imported
by the changed file, so the production context shows its signature and
docstring as an L4 block in both arms: the docstring says nothing is deleted
while `dry_run` is True and rows are removed when it is False. The new call
passes `dry_run=confirmed`, the wrong way round: a confirmed request only
counts the rows and an unconfirmed one (the preview an operator runs before
confirming) hard-deletes every row of the account. The changed file and that
L4 block are enough to see it; no caller or other file is needed.

Arm B retrieves one block, `erasure/intake.py`, through the `uses_imported`
edge to the changed `log_request`. It is unchanged, calls
`log_request(account_id)` exactly as before and is correct; it says nothing
about `purge_account` or `run_erasure` (nothing calls `run_erasure` yet), so
the finding does not need it. It is in the case so that the control also shows
whether extra, irrelevant context makes arm B lose the defect arm A finds. The
L4 definition `erasure/purge.py` is not retrieved.
