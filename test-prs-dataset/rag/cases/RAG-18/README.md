## Why only the caller of the caller shows the defect

It states no policy for a bad value, so the new exception simply passes through it. One row with a blank or malformed address now aborts the whole import with a `ValueError` after the rows before it were stored and before the rows after it are read; the caller gets an exception and no count. Neither the changed file nor the hop-1 block shows that a bulk loop over such rows sits above.
