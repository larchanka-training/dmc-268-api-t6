## Story

The diff changes the retry backoff of the task runner: the base delay constant becomes `BASE_MS = 250` and `retry_delay` now returns its growth from that base. ## Why only the caller of the caller shows the defect

`taskrunner/scheduling.py` (hop 1) imports `retry_delay` directly and only forwards the value: `next_delay(job)` returns `retry_delay(job.attempts)`. It names no unit, so on its own it is correct whatever `retry_delay` counts in. The consumer of the delay is the caller of that caller, `taskrunner/worker.py`: `run_job` passes `next_delay(job)` to `time.sleep`, which takes seconds. With `MAX_ATTEMPTS = 5` the failed job now sleeps 500, 1000, 2000, 4000 and 8000 s (about 4.3 hours in all) before it is given up, instead of 2 to 32 s, and holds its worker the whole time. The diff alone shows a rescaled constant, not who reads it as seconds; neither the changed-file context nor the hop-1 block mentions `time.sleep`.
