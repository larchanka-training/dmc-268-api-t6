## Story

A tidy-up of the blog module's public surface: `slugify` in `src/slug.ts` is
no longer exported, since `postPath` in the same file is the way to build a
post URL. The diff is the one declaration line, `export function slugify` ->
`function slugify`; the function itself stays in the module, so the removed
export leaves a changed RIGHT line to anchor on.

## Why only the caller shows the defect

The diff shows that an export is dropped, and nothing about who imports it:
the file's own users (`postPath`) still work and no other changed file is
involved. The one importer is `src/feed.ts`, unchanged and not in the diff. It
imports the old public name directly (`import { slugify } from "./slug"`) and
builds feed entry ids with it in `feedEntryId`. After the change the import
names something the module no longer exports: a compile error under a
type-checking build, a link-time error for the whole feed module when the
files are loaded as ES modules. Arm A shows no block of `src/feed.ts`; arm B
retrieves it through the `uses_imported` edge `src/feed.ts` ->
`src/slug.ts::slugify` (retrieved block about 47 estimated tokens, plus a
16-token block of the definition line in `src/slug.ts`).
