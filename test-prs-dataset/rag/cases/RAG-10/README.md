## Story

The sensor module moves to the sampling vocabulary of the new hardware
layer: `readSensor` in `src/sensors.ts` is renamed `sampleSensor`. The diff
is the one declaration line; the body and the return type are unchanged.

## Why only the caller shows the defect

The diff shows a rename and nothing about who still uses the old name. The
one caller is `src/alerts.ts`, unchanged and not in the diff. It imports the
old name directly (`import { readSensor } from "./sensors"`) and calls it in
`isOverLimit`. After the change the import names something that no longer
exists: a compile error under a type-checking build, a link-time error for the
whole alerts module when the files are loaded as ES modules, so no over-limit
alert can be raised. Arm A shows no block of `src/alerts.ts`; arm B retrieves
it through the `uses_imported` edge `src/alerts.ts` ->
`src/sensors.ts::readSensor` (retrieved block about 56 estimated tokens, plus
a 17-token block of the definition line in `src/sensors.ts`).
